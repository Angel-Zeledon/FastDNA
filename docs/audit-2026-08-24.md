# Full-codebase audit — 2026-08-24

Four parallel read-only reviews (Rust core, Rust I/O and strategies, auxiliary
modules and FFI, Python package and `fastdna-ml`), an exhaustive CLI probe
matrix, and the resulting fixes. Every finding below was confirmed by tracing
code or reproducing it against the release binary before it was fixed, and
every fix landed with a test written failing-first.

Test counts: Rust 160 → 198; Python package 243 → 252; `fastdna-ml` 0 → 7.

## Critical — silent data loss

| Finding | Fix |
|---|---|
| `-o`, `--qc` or `--histogram` pointing at the input file overwrote the user's FASTQ with the counts table, exit 0. Export runs after the input is fully read, so `File::create` truncated it. | `atomic::same_file` guard in `main.rs::run`, before any work; canonicalizing and case-insensitive on Windows. |
| All four writers (Parquet, CSV, histogram, QC JSON) truncated the destination in place. Any later failure — disk full, Ctrl+C, an Arrow error — left a corrupt half-written file where the previous good output had been. | New `src/atomic.rs`: write to a sibling temp file, `commit()` renames it over the destination; an abandoned write removes the temp and leaves the destination untouched. `GenomeSketch::save` too. |

## High — silently wrong results

| Finding | Fix |
|---|---|
| `jaccard()` stopped its union walk when the shorter hash list ran out, even when that sketch was *not full* and therefore held its complete k-mer set. The denominator shrank only: a measured 33x overestimate for a small sketch against a large one, ~15% systematic bias in ordinary use. `mash_distance` inherited it. | The walk now counts the longer list's remaining hashes as union-only members when the exhausted sketch was not full; still stops at the ceiling when it was full. |
| `FastqReader::from_path` used single-member `GzDecoder`, so `preview`, `sketch` and `hll` read only the first member of a real (multi-member) SRA/ENA `.gz` — disagreeing with the counting pipeline on the same file. | `MultiGzDecoder`, matching `main.rs` and `ffi.rs`. |
| `merge_buckets` opened every run file of a bucket at once. A bucket accumulates one run per worker per flush, so a ~6 GB FASTQ needed 1000+ simultaneous handles — over the default `ulimit -n`, failing at the merge phase after all the counting work, on exactly the inputs the disk strategy exists for. | Cascaded merge: passes of at most `MAX_OPEN_RUNS` (64) runs stream into intermediates until one final pass fits. Intermediates deleted per pass. |
| `sketch()` with `k` outside 1..=32 (or `sketch_size` 0) produced a silently empty sketch whose every later comparison returned 0.0, while `count()` and `estimate_cardinality` correctly rejected the same `k`. | `InvalidK`/`InvalidConfig` at construction and at `load()`. |
| `analyze_fastq_wasm` returned a successful zero-count result to the browser for out-of-range `k`. | Rejected with an error. |
| Cohort discovery silently dropped a FASTQ file whose name was not UTF-8 — a whole sample vanishing from a cohort with no trace. | Fails loudly, naming the file and the fix (rename it). |
| A raising `--min-quality` above the Phred+33 ceiling trimmed every base and produced a plausible-looking empty output, exit 0. | Rejected: 0..=93 only. |
| `--max-ram nan` parsed to a silent 0-byte budget, flipping the auto chooser to disk. | Non-finite values rejected. |
| `OUT.PARQUET` on Windows received CSV bytes (extension dispatch was case-sensitive); `FILE.GZ` was parsed as plain text. | Case-insensitive dispatch for both. |
| `spectrum.py`'s valley scan materialized one list entry per depth in a contiguous range; one adapter-dimer k-mer at depth 10⁷ built a multi-GB list. Reachable from `suggest_min_count()` and `assembly_qc`. | Walks the sorted observed depths, preserving the previous semantics for gaps. |
| `embed_cohort` mapped a duplicated path to its last index only, leaving the earlier duplicate's row all-zero — "identical to every sample". | Raises, naming the duplicate. |
| `train_classifier.build_feature_matrix` produced NaN features when a sample's frequencies summed to zero, and silently dropped zero-k-mer samples *and their labels* through an inner join. | Both raise, naming the file; duplicate sample stems and missing columns too. |
| `download_covid.py` fell back to writing 250k random reads into `sars_cov_2_real.fastq.gz` and exited 0, so the pipeline processed synthetic data labelled as real. | Mock data goes to `sars_cov_2_MOCK.fastq.gz`, prints a warning block, exits 3; `run_covid.bat` treats 3 as a hard stop. |

## Medium — misleading errors and API misuse

- A disk-strategy worker's real error (disk full while spilling) was stringified and rewrapped as `Internal`, reported as "internal error (this is a bug in FastDNA)" with the path and `source()` stripped. Worker failures now keep their type; only genuine panics become `Internal`.
- Output paths were checked for writability only after the whole counting run: a typo'd directory discarded hours of work. `preflight_writable` now probes every output path at startup.
- `check_signals()` clears CPython's pending-signal flag when it hands over the exception. `count()` discarded that `PyErr`, so a worker finishing inside the same 50 ms window swallowed the user's Ctrl-C entirely. The exception is kept and re-raised ahead of any worker outcome.
- `CountMinSketch::merge` asserted on mismatched dimensions (a panic on a `pub` type destined for the FFI surface) and `new` accepted `width == 0` (deferred divide-by-zero) and `depth == 0` (`u32::MAX` for every estimate). All are typed errors now. Half the row seeds were even, discarding the key's top bits — every seed is forced odd.
- `-m 0` (a meaningless cutoff) and `--max-count` below `--min-count` (a band that keeps nothing) both completed with exit 0 and an empty output; both are rejected.
- `interop` silently substituted uniform Q40 for a quality-length mismatch (now warns, naming the record); `interpret` wrote CRLF FASTA on Windows (now LF); `sklearn` turned a bare string `X` into per-character `FileNotFoundError`s and double-counted duplicate paths (both raise clearly); `multiomics` accepted negative `top_features` by slicing from the end.
- `quality_trim_end` indexed `qual` with bounds derived from `seq`, panicking on a length-mismatched record built through the public API. It clamps to the shared prefix.
- `FASTDNA_SPILL_DIR` added: scratch space no longer forced onto the (often small) system temp drive.

## Verified sound

Reviewed adversarially and found correct: `kmer.rs` k=1/k=32 shift edges and
ambiguous-base window resets; `counter.rs` saturating merges and compaction
seams; `qc.rs` merge associativity and finalize-once discipline; `pipeline.rs`
config validation, channel-drain discipline, `catch_unwind` + `panic="unwind"`
contract; `mem_estimate` saturation and fallbacks; `hll.rs` register math and
merge; `sketch.rs` bounded containment estimator and load invariants;
`ffi.rs`'s exhaustive error→exception mapping; `sklearn.py`'s estimator API and
leakage boundary; the `kmer_u64/kmer_sequence/frequency` schema contract,
re-verified end to end against real SARS-CoV-2 engine output feeding the ML
feature matrix.

## Exercise matrix

59 CLI probes against the release binary (formats, k=1/k=32, quality and count
bands, thread counts, all three strategies, unicode paths, multi-member gzip,
CRLF, lowercase bases) plus every error path (missing/directory/garbage/FASTA
/truncated-gzip inputs, unwritable and colliding outputs, every invalid flag
value). All pass; no probe produces a panic, a hang, or a zero exit on failure.

## Known remaining gap

A hard kill (Ctrl+C, OOM) still orphans the scratch directory: the CLI has no
signal handler, so `ScratchDir`'s `Drop` never runs. `FASTDNA_SPILL_DIR` lets
users place it where that is survivable. The root fix is graceful cancellation
in `main.rs` (the pipeline already accepts a cancel token) — worth doing next.
